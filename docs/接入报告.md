## 4. 与"默认配置示例"的偏差（依据：实测）

1. **designer 不用 uvx**：uvx 建 venv 时复制商店版 Python 的
   `...\Lib\venv\scripts\nt\python.exe` 报 os error 6000「无法加密指定文件」（EFS 复制问题）。
   → 同源 PyPI 包直装 E 盘 venv；mcp 钉 `<2`（包代码仅兼容 mcp 1.x fastmcp API）。
2. **powerbi 不走 `npx github:AjvoGod/powerbi-mcp`**：参考机 git TLS 证书链异常，运行时拉取必失败。
   → 本地 clone + npm install + tsc 构建后 `node dist\index.js` 直跑。
3. **modeling 的 args 含 `--start`**：官方 mcp.json 配置即含该参数。

## 5. C 盘写入点清单（附录 B 豁免项）

- 已存在组件（未迁移/未改配置）：Node、npm 全局包与 npx/pnpm、商店版 Python/pip、git、DSH 本体。
- 本次新增 C 盘写入：**无**（下载/缓存/venv/源码/项目均在 E 盘；个别早期命令用过系统默认 TEMP 的临时文件除外）。
- 若安装 Power BI Desktop：安装目录 `C:\Program Files\Microsoft Power BI Desktop` + 用户数据 `%LOCALAPPDATA%\Microsoft\Power BI Desktop`。
- **用户数据已实测可迁移（补记）**：`%LOCALAPPDATA%\Microsoft\Power BI Desktop` 实测 **300 MB / 1508 文件**（`WebView2\` 占 ≈257 MB），已用 **junction** 整体搬到 `E:\WBData\local\PowerBI-Desktop`，**原路径不变**，Desktop 与三个 server 均不受影响；映射已登记进登录守卫。做法见 [`desktop-userdata-to-e-drive.md`](./desktop-userdata-to-e-drive.md)。

删除 cordis.patch.yml 末尾追加块并保存（自动热重载）；清理可选：删除 venv / 本地构建 / 测试项目目录。

## 8. Power BI Desktop 接入（2026-09-11 完成）

三个 server 的 Desktop 能力均已实测通过：`powerbi-modeling` 原生发现并直连本地 AS 实例（ListLocalInstances → Connect → 列库 → 读模型）；`powerbi-designer` 需 `POWERBI_DESKTOP_PATH` 指向实际位置；`powerbi` (AjvoGod) 的 Desktop 发现与提取需应用仓库内补丁 `patches/powerbi-mcp-desktop-discovery.patch`（端口文件位置/编码、ADOMD 程序集加载、DMV 列集差异，共四处）。

完整记录（含环境事实、补丁说明、配置片段、验证方式与注意事项）见 [`powerbi-desktop-integration.md`](./powerbi-desktop-integration.md)。

C 盘写入点补充申报：Desktop 程序本体位于 E 盘；用户数据目录 `%LOCALAPPDATA%\Microsoft\Power BI Desktop`（Desktop 强制写入该路径）**已用 junction 迁至 E 盘，原路径保留为联接**，因此当前 C 盘无持续性写入。把程序本体移出 C 盘会使 HKLM 中的 MSI 记录失效，升级/修复前需注意。**修正**：早前版本写"用户数据不可重定向"，实测不成立，详见 [`desktop-userdata-to-e-drive.md`](./desktop-userdata-to-e-drive.md)。
